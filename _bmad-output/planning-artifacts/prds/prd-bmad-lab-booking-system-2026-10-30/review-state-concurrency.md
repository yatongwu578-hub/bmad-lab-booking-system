# Reviewer Gate — 状态、时间、并发与FR可验证性

日期：2026-11-03。依据当前 `prd.md` 与课程基线独立静态审查，未读取其他Reviewer报告，未改PRD或既有意见记录。课程约束先读；本报告不代表运行测试、人工批准或M1通过。

## 总体判断

当前18条FR均有可观察后果，五种状态及时间边界可以构成一致的业务状态机。没有发现必须重新打开九项团队决定的矛盾，亦未发现critical/high级业务阻塞。存在1项medium级的时间判定取证口径澄清建议、1项low级的交错验证覆盖提醒，均不要求新增功能，不应把正常架构/测试设计待办升级为业务范围阻塞。

计数：critical 0，high 0，medium 1，low 1。架构阶段业务blocker：0。

## Findings

### SC-01 — medium：跨开始边界请求的“判定时刻”应在架构/测试交接中统一

- **证据**：§3以“操作判定时刻”定义尚未开始，FR-006要求开始严格晚于“提交判定时刻”；FR-012要求“处理时重新判定时间”，FR-018以“判定时刻大于或等于预约开始时间”决定失效。文本明确服务端时间判断和统一时区，但未进一步约定跨边界请求的业务判定点及其证据。
- **具体场景**：预约10:00开始。管理员9:59:59发出批准，服务端在开始前进入处理，而状态修改/响应跨过10:00。若取页面或请求到达时间，可能批准；若取实际审核决定时间，则可能失效。FR-012已排除仅信页面旧状态，但后续架构/用例仍需要选定可复核的服务端决定时刻。不能凭响应到达晚于10:00，就反推一次开始前已经合法完成的批准违法。
- **影响**：若不同操作自行选时点，边界测试可能对同一交错给出不一致判断；这是“如何验证既定时间边界”的细化，并非要求改为严格先到先得、增加临时锁或延长时间窗口。
- **最小建议**：交接时明确各操作采用可信服务端、与业务决定相一致的判定时点；同一决定中的时间/状态/占用判断使用一致口径，保存可核对判定时刻。必要时在PRD §3加一条不指定技术的解释；具体一致性点、事务和锁由架构选择，不在本报告代选。
- **处理建议**：作为架构设计及验收设计待办记录，负责人为架构/测试负责人；在定义时间边界测试与一致性方案时复核。若团队希望在PRD直接写死“请求接收时”或“提交完成时”，须先人工决定，不能自动替换现有规则。
- **是否阻碍架构阶段**：否。既有规则足以要求服务端在合法业务判定时点检查；架构本就需要落实该时点与并发证据。本项不能作为“当前已存在过期获批bug”的断言。

### SC-02 — low：补充验收列举偏重失效交错，设备状态交错也应留在后续覆盖表

- **证据**：FR-008第一段明确“申请与停用、批准与取消”等交错；NFR-001主实验是20个申请请求竞争，补充验收主要列出“FR-018…与查询、管理员审核和新申请冲突判断交错”。
- **具体场景**：设备停用与新申请交错；设备停用与批准交错；管理员批准与本人取消交错。FR-008/012/017已经给出可接受的串行化业务结果，但若实施者只照NFR-001明列的实验执行，可能没有保存这些原本已要求的交错证据。
- **最小建议**：后续架构/故事/测试设计显式列入上述FR-008已有场景，并对照各自先后顺序核验结果；无需增加NFR编号、并发数量、轮次或新的功能。可将NFR-001补充验收的交叉引用写成“FR-008列举的全部交错类别”，作为文档澄清候选。
- **处理建议**：测试负责人在将FR-008映射到故事及自动化测试时复核。当前不虚构这些用例已执行，不凭缺独立测试矩阵判定FR不可验证。
- **是否阻碍架构阶段**：否；属于已知规则的验证覆盖交接。

## 状态与边界推演（文档推理，非执行测试）

| 场景 | 当前可得的业务结果 |
| --- | --- |
| 同设备相同/部分重叠/包含区间 | FR-007与§3公式均拒绝有效重叠。 |
| 同设备首尾相接 | `开始A < 结束B 且 开始B < 结束A`不成立，可以同时存在；不引入缓冲。 |
| 同一用户、不同设备、同时间 | 允许；不追加人级冲突。 |
| 待审核，开始前 | 可依权限批准、拒绝或取消；设备不可用不得批准。 |
| 待审核，恰到/超过开始时间 | 查询/处理/冲突判断时只能失效，不批准、拒绝或取消；历史保留。 |
| 待审核，已超过结束时间且此前无人访问 | 有权限查询时同样满足已到开始条件，转为失效；没有后台扫描要求。 |
| 已批准，开始后但结束前 | FR-018不误失效；用户不能取消，管理员可带原因取消。 |
| 已批准，恰到结束时间 | 管理员不得取消；占用仅原区间，后续相邻申请不冲突。保留已批准历史是既定范围，无需新增已完成状态。 |
| 已拒绝/已取消/已失效 | 不占用、不重新打开；重新申请独立校验。 |
| 设备停用或维修 | 禁新申请/批准，不自动取消或失效已批准预约；本人记录同时显示当前设备状态。 |
| 待审核10:00～12:00，10:30提交11:00～12:00新申请 | 旧待审核按需失效；新申请是合法未来整点区间，不再被旧记录阻止。不能把释放理解为可补约已开始的10:00～11:00。 |
| 多个查询同时触发失效 | FR-018要求重复检查不重复生成转换，FR-008禁止失效后复活；实现机制留待架构。 |
| 未授权请求触发查询/处理入口 | FR-002/018及NFR-002要求拒绝、无泄露、无业务数据修改。 |

## FR可验证性覆盖

| FR | 最低可观察后果 |
| --- | --- |
| FR-001/002 | 有效/无效登录与权限路径，返回结果、详情及前后数据可比对。 |
| FR-003/004 | 设备必要字段、当前状态、给定设备日期下占用集合、隐私字段可核对。 |
| FR-005/006 | 成功记录及待审核状态；非法时间、设备或权限失败原因与无占用后果；明确整点/同日/开始边界。 |
| FR-007/008 | 区间冲突和串行化允许结果可推导，并发唯一占用可断言。 |
| FR-009/010 | 本人五状态与当前设备状态、原因可见；取消时间与归属边界及释放历史可验证。 |
| FR-011/012 | 设备筛选集合及时间/状态过滤；批准仅限开始前可用设备待审核，不能覆盖其他终态。 |
| FR-013/014 | 拒绝/取消的时间、状态、原因及释放后果可验证。 |
| FR-015/016 | 操作留痕字段、系统失效与人工操作区分；设备编号唯一/不可改、不可物理删除和关联保留可验证。 |
| FR-017/018 | 设备状态改变及原记录保留；按需失效、历史与占用一致、不复活及重复触发可验证。 |

无须为每个FR机械复制一段Given/When/Then才称可验证；现有条文可直接形成断言。未来故事必须继承相应条件和后果，不能退化为“功能正常”。本报告不新增事务、数据库、调度、队列、性能指标或首版功能。
