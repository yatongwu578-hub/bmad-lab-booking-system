## 1. 单独批准的唯一授权增量

负责人另行明确批准正式目标、对象所有者、操作者、窗口及指定演示设备和四项输入，并说明测试后是保留还是恢复原值。没有这些决定，不执行 GRANT 或业务写入。

```sql
GRANT UPDATE (name, category, location, description)
ON TABLE public.equipment_equipment TO lab_booking_app;
```

候选四列覆盖实际 `UPDATE` 的 SET 列，也满足 `SELECT FOR UPDATE` 至少一列 UPDATE 的要求。既有设备七列读取用于锁定主键和重读。R1 锁后按账号主键查询 `is_active`、`role`，复用已有账号表 SELECT，不增加账号写权限。 [PostgreSQL 17 SELECT](https://www.postgresql.org/docs/17/sql-select.html) · [PostgreSQL 17 UPDATE](https://www.postgresql.org/docs/17/sql-update.html) · [PostgreSQL 17 GRANT](https://www.postgresql.org/docs/17/sql-grant.html)

## 2. 获批后执行前后核对

1. 由既有设备表所有者 `lab_booking_migrator` 使用受保护密码文件，连接批准的正式目标 `127.0.0.1:5433/lab_booking`。在同一事务内校验实际库、地址、端口、17.12 版本、会话和当前角色、对象归属及实际列清单。保留授权前的有效权限及角色继承核对单。既有 SELECT／INSERT、账号读取或拥有者与留档不符时停下调查，不扩大授权修通。
2. 使用单事务且遇错即停的批次，在授权前后根据 `has_column_privilege` 与 `has_table_privilege` 核对有效权限，包括继承、PUBLIC 和转授权。唯一新增为四个设备列的 UPDATE。ID、编号、状态无 UPDATE，设备表无表级 UPDATE、DELETE、TRUNCATE 或其他新增表权，不给转授权，不改变角色成员关系、测试角色、账号表权限、序列、库／模式 CREATE 或迁移状态。
3. 前后断言都通过才提交，否则回滚权限事务。提交后另开实际运行角色连接进行只读复核。若提交结果未知，先独立读取 ACL 再判断，不自动重放授权批次。没有批准即不执行回滚式权限变更或额外补权。
