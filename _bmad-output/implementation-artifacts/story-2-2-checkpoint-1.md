## 实施口径

1. 在设备详情显示有标签的日期表单，提交到拟定 `GET /equipment/<pk>/occupancy/?date=YYYY-MM-DD`，结果页可以改查日期和返回详情，不替换申请、编辑、目录导航。查询不按设备状态隐藏。先认证并检查有效业务角色，再严格解析日期；缺值、格式错、闰日或日期范围不可表示给 400，设备不存在给 404。两者都不扫描预约或收尾。非 GET 不进入业务逻辑，响应不缓存。
2. 在 Story 2.1 的最外层短事务内，先核对三角色授权和设备存在，再按 `equipment_id = 目标 AND start_at < 次日日首 AND end_at > 当日日首` 固定 ID。显式使用 Asia/Shanghai 的半开自然日，不用 UTC 日期、不用 `end_at > t_decision` 预筛、不用 FR-006 判查询日期。存在待审候选就锁且只锁这行设备。锁后核对账号启用与角色，分别重读设备和固定 ID 预约，再独立采样一次 `clock_timestamp()`。无待审分支不取设备写锁，仍在展示前复核权限并用一次数据库时钟作分类。后续到期查询、状态写入和展示都限固定 ID 与原设备／日期，不扩入并发新增。收尾用已核准的 `_expire` 和历史写入，不重写 2.1 提交机制。
3. 用同一个时刻分类。未开始待审有效，到开始即失效。已批准在开始前是未来占用，`start_at <= t_decision < end_at` 是进行中占用，`end_at <= t_decision` 仍显示所选日期的历史区间，但不算当前或未来占用。已拒绝、取消、失效不显示为占用。只返回显示所需的区间与类别，不传申请人、预约 ID、详情链接、原因或历史行。页面把设备当前状态、占用与未占用、最终可否提交分别表达。标明固定候选和判定时刻口径，不承诺快照或可预约。
4. 数据与历史提交后再构造正常响应。数据库确认失败或回滚与提交未知均给 503，但文案区分，不显示空结果或盲目重试。未知情况下不在响应中推断状态或历史是否持久化。无业务库操作、无迁移／授权、无审批／取消／2.3／2.5，不提前做统一视觉优化。

## 验收设计

| 正式 AC | 最低验证与证据 |
| --- | --- |
| 1 · 日期占用 | 不同设备、不同北京日期、各状态、半开日期边界及 UTC／北京时间跨日夹具。分开验证 10:30 的 10–11 点已批准、同区间待审。已批准在开始前／等／后、结束前／等／后和历史日期中有正确标签，完整历史区间保留，设备状态独立。 |
| 2 · 失效 | 目标日过期待审含已结束，原状态与系统历史在独立连接回读匹配，实际执行者为系统且判定时刻一致。重复查询零新增历史，未到期和已批准不写，不触及日期／设备外候选。 |
| 3 · 锁与取时 | 候选 SELECT 和实际绑定在锁前，单设备锁、账号复核、固定 ID 重读、唯一取时和失效顺序取证。真实等锁跨开始，另测无待审、空候选皆不额外加锁。 |
| 4 · 冻结 | 另一连接持目标锁，观测查询冻结并阻塞后提交新预约。首次不显示也不收尾该新增，下次纳入并按时刻判定。分别覆盖从合法提交产生未来待审，以及到点新增的旁路测试夹具。 |
| 5 · 权限和投影 | 学生、教师、管理员从实际详情日期入口读取他人占用，响应和模板上下文无受限字段。匿名、停用会话、锁中撤权等成对验证拒绝、无泄露、无业务变化。合法对照单计，报告本入口实际分母，不计为全项目 NFR-002。 |
| 6 · 输入及空结果 | 缺日期、无效日期、合法不存在设备均明确，记录无预约扫描／DML／锁。有效日收尾后空结果为 200，文字与状态不是错误。 |
| 7 · 三层语义 | 可用／维修／停用、空日和过去查询不显示为保证可预约。先查未占用，另一请求提交 201，原用户随后同区间提交 409，独立查库只有胜者有效。 |
| 8 · 原子和异常 | 真实 PostgreSQL 故障注入，至少覆盖后续历史写失败造成前面所有状态／历史共同回滚，以及提交阶段确认失败和丢确认未知。未知用独立观察区分实际持久化或未持久化，HTTP 不宣称任一。记录 SQLSTATE、是否重试、响应、状态和历史前后快照。 |

T-01 使用真实隔离 Django HTTP、PostgreSQL 独立连接及 `pg_blocking_pids` 证明提交先和查询先两种顺序。提交先并已完成失效时，查询锁后读到新状态不重复写。查询先持锁并收尾时，提交等待后按自身判定重查，设备外合法操作不被目标锁阻塞。T-02 区分精确测试专用边界与真实数据库时钟，保存等待跨开始以及判定后提交跨界的顺序。T-03 保存实际 URL、身份与投影验证，权限不通过不得继续采样、写预约或历史。保留实际绑定和后续独立读回，不用 sleep 或 mock 假造真实锁等待。日期和合法申请夹具按数据库当前时刻动态生成，不改系统时钟。
