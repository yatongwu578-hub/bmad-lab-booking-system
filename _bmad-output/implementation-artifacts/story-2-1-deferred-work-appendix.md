- **P04（原始 #6，Medium）SQL 采样断言未完全冻结锁与业务语句顺序。** 理由：源码和原始真实 SQL 可核对设备按主键加锁、锁后目标及账号重读、唯一业务时间，并核对当时的冲突与写入顺序。当前 AC-7／NFR 证据不依赖这个宽松断言单独成立。 残余风险：将来探针可能放过错误锁谓词或业务语句被提前。 后续节点：首次调整设备锁、业务时钟、SQL 形态或共用事务探针时，补全表名、主键谓词和采样前后顺序断言。
- **P05（原始 #9、#19，Medium）多条同设备到期预约及后一次历史写入失败未组合验证。** 理由：当前遍历全部到期记录，同一外层事务追加历史。I4/I5、F1/F2 已检验真实单记录失效及事务回滚，未见部分提交，AC-6/8/9 的现有关键路径有证据。 残余风险：多条批量情况下出现截断或后项失败，现有单条夹具可能漏检。 后续节点：首次调整批量失效或 Story 2.2 复用 FR-018 时加入同设备多条和后写入失败组合。
- **P06（原始 #10、#18，Medium）本人 GET 的失效写入缺少确认失败和未知两类注入。** 理由：本人 GET 与 POST 共用已验证的持久事务和异常分类封装，GET 分开处理 503，正常路径有真实失效、重复读取及历史证据。未见当前误报或重复历史。 残余风险：以后 GET 分支改动可能遗漏其提交未知或失败回滚语义。 后续节点：本人结果读取或历史事务下一次改动时补 GET 注入及重复读取，独立回读状态和历史。
- **P07（原始 #8，Low）拒绝正文全字段与真实跳转断言不完整。** 理由：现有逐例拒绝、同一业务快照、无锁／无时钟、异主等价不存在均有证据。P02 另行强制验证同角色异主不泄露且无副作用，不将该缺口随本项延期。 残余风险：未来只泄露时段或状态，或登录 next 路径退化，现有其他拒绝用例可能漏检。 后续节点：下次维护 T-03 权限矩阵和匿名登录导航时扩充逐字段与真实跟随。
- **P08（原始 #20，Low）确认页和本人页未逐字段冻结显示。** 理由：现有模板确实显示编号、设备、完整北京时段和状态，开发原始响应与库行一致。P01 后的独立页面导航仍会核对实际显示，不因延期取消该运行证据。 残余风险：将来页面遗漏结束时间等字段，原常规回归可能继续通过。 后续节点：下一次预约结果页面或 Story 2.3 显示字段回归时，把完整显示断言纳入常规套件。
- **P09（原始 #21，Low）两个 409 文案验证复用生产常量。** 理由：当前不可用与冲突的正文实际不同，I2/I5 和 200 个响应已有独立于常量的原始记录核对，NFR 不把不可用算冲突。 残余风险：未来常量误改时，使用同一常量作期望可能放过两条文案相同。 后续节点：下次维护申请拒绝文案或 AC-4/AC-5 回归时固化独立预期。
- **P10（原始 #22，Low）POST 缺少足够的偏移和秒级精度拒绝用例。** 理由：源码直接传原值到严格解析器，已有 helper 边界断言，当前未见绕过。P01 不改变服务端规则，整改后本次独立复验仍检查服务端拒绝，延期的是扩大常规覆盖矩阵。 残余风险：未来 view 截断输入可能绕过秒和偏移限制，单测不一定捕捉。 后续节点：下一次修改预约输入解析或补充 T-02 HTTP 矩阵时增加非零秒及偏移，核对无新增行。
- **P11（原始 #23，Low）历史记录时间断言未冻结它与判定时刻的区别。** 理由：实际写入用 statement_timestamp()，取证保存业务 decision_at 和记录时间，R-04 与原子性有独立约束和事务证据。 残余风险：未来错把 decision_at 作为记录时间，现有非空和范围断言可能仍通过。 后续节点：第一次改动审计写入或增添后续历史动作时，补可分辨的数据库写入窗口。
- **P12（原始 #11，Medium）续跑允许整份工具变化时继承历史结果。** 理由：开发原始阶段、真实业务版本和两个实际工具改动已经逐项核对。后续独立复验在整改版全量实跑，不能用旧标记代替。 残余风险：将来改动已复用阶段的断言仍可能继承绿灯。 后续节点：下次启用跨版本续跑前按阶段绑定真实执行输入，涉及变更必须重跑。
- **P13（原始 #17，Medium）续跑未强制核对被复用 JSONL 的内容完整性。** 理由：当前 99 份原始记录、退出码、逐验证组计数和清理已另作离线核对。NFR-001 结论依据逐响应，不依据单一成功标记。 残余风险：将来缺失或截断的记录仍可能被包装器缺省接受。 后续节点：下次复用历史原始证据前增加存在、结构、计数、清理和散列验证。
- **P14（原始 #3，Low）提交未知缺少安全可关联的服务端诊断。** 理由：现有业务已区分 503 的确认失败和待核查，保持一次尝试，不虚构成功或自动重试。操作诊断不改变正式结果语义。 残余风险：真实运行遇到未知结果时定位阶段和关联数据耗时。 后续节点：运行诊断方案审查或再次出现未知提交时，设计脱敏、非敏感关联信息和保留策略。
- **P15（原始 #4，Low）本人结果 GET 待核查文案误用提交语义。** 理由：文案不宣称回滚，不执行新建，不自动重试。GET 状态与历史由数据库决定，未见安全或一致性影响。 残余风险：用户可能误以为自己刚提交了一笔新请求。 后续节点：下次维护结果页错误文案时区分查询与申请，并核对不承诺不实结果。

- **P17（原始 #13，Low）迁移阶段退出零未单独区分真实应用和 no-op。** 理由：历史标准输出明确有两条 Applying ... OK，且有迁移／表前后证据。已迁移隔离库的后续 no-op 不能替代初迁证据。 残余风险：后续摘要阅读者可能把 no-op 看成首次迁移。 后续节点：下次迁移预演、迁移包装或发布记录更新时明确实际应用数。
