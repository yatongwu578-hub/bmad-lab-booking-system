## A · 只读资格与样本

1. 到获准的正式窗口才运行 [2.5 只读检查](story-2-5-review-support/inspect-story-2-5-w01.ps1) 的 `-CaptureSnapshot`，不带 `-ToolFixture`，选择实际空闲本机端口。必须读回 `127.0.0.1:5433/lab_booking`、`lab_booking_app`、PostgreSQL 17.12、`EXACT_COLUMNS_PRESENT` 和零缺列，保持已有业务、会话、历史列权及禁止转授。复用 [W01 阶段的只读迁移账本查询](story-2-5-review-support/run-story-2-5-w01-formal.ps1)，不启动该发布入口，不执行迁移。2.4 不新增数据库对象或 SQL 投影，预计现权足够。发现权限或迁移漂移只留证并停止，不自动 GRANT 或 migrate。
2. 用现有启用学生/教师账号和预约。2.5 既有检查提供全库风险上界，不能用管理员候选冒充本人样本。若要缩小范围，在同一类只读快照用当前账号 ID 核对样本归属，并按 **整个本人列表范围** 统计任何 `pending` 且 `start_at <= safe_until` 的记录。详情以目标 ID 单独核对，开始时刻使用数据库时钟。全库风险非零不推断每个本人列表都不安全。如未能可靠验证本人的完整范围，就跳过该列表，不借访问触发 FR-018。
3. 优先选已存在、在本次窗口内仍未开始的本人待审核或已批准预约。临开页面再核对即时窗口、账号启用及样本归属。没有合格现存预约，则记录正向现场未覆盖，以已通过的隔离正例承接。若只有详情/确认可安全直访，可以只记录这段，不冒称通过完整「我的预约」往返。不要固定历史的预约编号或把无写授权扩大到收尾。

## B · 只读路径的 Chrome 自动取证

- 复用 [2.5 W01 日志契约](story-2-5-review-support/w01-log-contract.ps1) 的 `Start-W01Redirected`、原生退出与行标记、严格 UTF-8 数据和原始诊断分离；HTTP 就绪与 PID 必须一致，活日志只经 `FileShare.ReadWrite` 读，不读在写的重定向文件。试验进程只绑定实测空闲的 loopback 端口，不接管旧进程。
- 复用 [2.5 WSGI 守卫](story-2-5-review-support/serve-story-2-5-w01-smoke.py) 与 [Chrome CDP 取证](story-2-5-review-support/capture-story-2-5-browser.mjs) 的能力，只需要路由／点击序列的定向配置或最小适配，不能把旧 2.5 管理路由脚本原样运行成 2.4 证据。维持已有 SQL 分类和凭据处理，**阻断所有取消 POST 和业务 DML/DDL**，只允许已知登录、退出会话技术写和预置账号的既有 `last_login` 更新。白名单仅含登录、身份、退出和预检通过的本人列表、对应详情或确认 GET。业务列表若到期跨界由写守卫停止，不将守卫拒绝算作产品正例。
- 正例优先用一个合格本人账号，从「我的预约」点实际「取消预约」链接，检查确认内容及存在原生表单，只点击放弃／返回，核对原状态仍可见。两种角色的真实成功提交已在独立 Chrome 验证，不必为正例再取消。负例对同一既有确认路径最少取匿名 302、异主 404；有现存管理员账户时可顺手核对 403。若合适，配一个不存在对象的 404 内容同形。无权请求不含预约信息，不把现场 guard 阻断的 POST 当作应用拒绝证据。认证、CSRF 恶意格式、到期、重复、锁与故障沿用已通过的隔离证据。
