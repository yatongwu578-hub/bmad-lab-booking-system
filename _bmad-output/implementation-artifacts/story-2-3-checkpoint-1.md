## C1 设计决定与足迹

- **意图缺口** 无。单一用户目标，列表、详情、导航和验证不可拆为独立交付。沿用既有 URL `/reservations/<pk>/result/`、路由名和 201 提交确认，保留单条详情链接并增加列表链接。新建 `GET /reservations/`，从师生身份页和预约成功页可点击进入；列表往返详情。复用同样布局，无统一美化、无新前端依赖。优先按开始时间倒序、ID 作稳定次序，不静默截断历史。继续沿用最小详情的无待审不取时契约；空候选不锁。
- **不可逆行为** 在 Step 2 无。产品中合法 GET 的唯一业务副作用是正式 FR-018 持久失效及配套历史。无需迁移、删除或数据回填；正式库列级授权与运行后续单独审批。本轮无数据库写入、更无部署。
- **足迹** 集中在 `reservations`、`audit` 受控原因读取、`accounts` 身份页导航及本 Story 验证。锁、时钟、历史写入、异常分类和 2.1/2.2 业务路径保持原有行为。页面只处理参数、调用服务和渲染，不直写。衔接旧接口时保留成功页原有设备、起止时刻及状态契约。
- **固定候选和提交** 从服务端身份限定预约，单条详情同时限定 PK。首次投影只冻结 `(pk, equipment_id, status)`；待审设备去重、主键升序逐个锁。锁后在事务内复核账号，按固定 ID 和同一申请人重读，随后对有待审候选的事务独立取一次 `clock_timestamp()`。现有 `_expire` 只接固定候选，采用其更新结果返回最终状态。无待审分支不加设备写锁且无须取时，仍复核身份。设备当前状态从本次读取，不将历史版本当当前；原因和详情只在授权候选范围查询，模板渲染在事务外。不可访问与不存在使用同样 404 内容且无副作用。未知结果分支不自动重试，不返回旧的成功页面。
- **原因投影** 仅对本人已拒绝或管理员取消预约，按固定 PK、终态对应动作及历史执行者类型选取原因。夹具使用 `reject`／`cancel` 和 `actor_type=admin`；本人取消、失效、无有效对应历史、空原因均不呈现原因。用历史 `id` 确定读取顺序，数据库的 `history_exactly_one_matching_object` 保证预约外键非空时指向预约对象，无须读取 `object_type`。不以执行人当前账号角色反推旧操作，模板自动转义，只输出原因文本，绝不回传操作者、其他动作或完整历史。只写读端识别和夹具，不加后续操作代码。

## 历史列权

D-042 已执行的授权和 Story 2.2 正式前后实际 ACL 证据均显示，`lab_booking_app` 对 `public.audit_operationhistory` 的历史读权只有 `id`（支持既有 `RETURNING id`）；设备状态、预约和账号需要的列权沿用现状。此次只读连通到 127.0.0.1:5433，但沙箱无法访问保护的 passfile，`psql` 以 2 退出，未读取实时 ACL 或业务数据。按最近已核验的授权，**本 Story 在正式运行前需要补历史列级读权**，除非新的只读复核证明以下精确授权已经存在。该结论不阻塞隔离库开发，授权不能随 Checkpoint 1 批准而隐含获批。 [既有 GRANT](story-2-1-targeted-independent-recheck/d041-authorization-recovery-reviewed.sql) · [2.2 正式前后核对](story-2-2-runtime-handoff.md) · [前后 ACL 原始回执](story-2-2-runtime-20261127-000918-77eb9198/acl.jsonl)

候选 SQL 仅用于审批，不在本轮执行：

```sql
GRANT SELECT (reservation_id, action, actor_type, reason)
ON TABLE public.audit_operationhistory TO lab_booking_app;
```

不赋表级 SELECT，不开放 `actor_id`、时间、其他列、转授、序列或额外写权。正式授权前后以运行角色在 `READ ONLY` 事务核对限定列和表级负对照，保持原权限与 schema。查询明确限定 schema、表别名及列；有效列权使用 `has_column_privilege`，不展开 ACL 空数组。若还需核对显式 ACL，用 `aclexplode(CASE WHEN pg_catalog.cardinality(acl)>0 THEN acl END)`，不将 NULL 变成零维空数组。不运行 GRANT 或变更正式数据作为预检。已另备普通 PowerShell 只读 ACL 工具 read-story-2-3-audit-acl.ps1，语法检查通过，正式库实时结果仍待核对。

## 逐条验收设计

| 正式 AC | 真实证据与断言 |
| --- | --- |
| 1 · 全部历史与详情 | 学生甲、学生乙、教师，跨北京日期、设备及五态数据；逐行冻结编号、设备、日期、完整起止和预约状态，核对已结束、维修／停用记录仍在。沿身份页和真实 201 页点击进入，所选详情与编号相符，返回列表。 |
| 2 · 设备当前状态 | 同一已批准预约依次用隔离夹具改变设备为可用／维修／停用，列表及详情对照实际 HTML，设备状态更新，预约状态不变，无自动转换或改历史。 |
| 3 · 原因授权 | 拒绝、管理员取消和本人取消、系统失效、他人及无匹配历史成对对照；核对实际文本与来源一致、HTML 转义、无完整历史及身份泄露，原因无匹配时不造值。 |
| 4 · 按需失效 | 覆盖开始前／相等／之后和已结束待审。合法列表、详情持久转换，独立连接核状态、失效后的有效占用、原申请字段、系统执行者和一次历史。与同设备他人到期待审、已批准和重复读取配对。 |
| 5 · 锁序与统一时刻 | 用逆序夹具和第三无关设备，从实际 SQL 绑定和独立连接确认候选冻结、设备 PK 升序、复核／固定重读、一次取时、状态／历史写入和提交顺序。无待审不锁；锁中撤权不得继续检查或写入。 |
| 6 · 逐例隔离 | 匿名、管理员、停用账号、同角色异账号、跨角色详情、伪造归属参数和不允许的 HTTP 方法；拒绝或参数无扩权，响应与模板均无他人数据，前后预约、设备、占用、历史不变。参数忽略的合法本人响应与未授权拒绝分开记录；合法师生对照单列，本入口 NFR-002 实际分母不冒充全项目。 |
| 7 · 固定候选与空态 | 用独立连接在查询冻结后提交新本人预约，本次排除、下次纳入；用同一授权角色验证无预约为 200，缺失与他人详情均为 404，正文相同。 |
| 8 · 原子与未知 | 两台设备触发失效，在第二条历史写入注入真实 PostgreSQL 故障，关联 SQLSTATE、实际执行绑定和独立前后快照；再验证提交确认失败、丢失提交确认情况下的 503。独立观察者辨别确实持久化与未持久化，HTTP 未知都不承诺任一，不自动重试，也不回退旧列表。 |
