# Story 2.1 · 发布前静态核对与正式库操作计划

D-040 单次隔离复验已通过，独立评审未见新增阻塞。本文件不授权发布，也不是正式库实测。**本轮没有连接正式库、没有执行 SQL 授权或迁移、没有请求正式 HTTP 服务，也没有启动或停止服务。** 三人共同操作和审阅，不按个人拆分。按 [候选迁移和列级 ACL SQL](runtime-release-plan-draft.md) 与下列顺序，获另行批准后逐关留证。

| 顺序 | 操作与停机条件 | 当下核对结果 |
| --- | --- | --- |
| 1 · 定目标和窗口 | 保存可恢复备份及确认窗口。所有正式连接显式固定 `127.0.0.1:5433/lab_booking`、PostgreSQL 17.12。迁移使用原 .venv 和 `LAB_BOOKING_DB_MODE=migration`，会话角色 `lab_booking_migrator`。本机应用用 `runtime`、`lab_booking_app`。只核对受保护的 passfile 存在，不显示内容。任何角色、host、port、库名、版本、schema、搜索路径或旧对象权限漂移均停。 | 仓库数据库配置与 README 对应。正式机连接、实际 ACL 与数据未验证。 |
| 2 · 只读迁移计划 | 在已批准的目标确认 `manage.py migrate --plan` 仅有 `reservations.0001_initial`、`audit.0001_initial`，迁移后的两表必须保持 R-04 两个真实对象外键、CHECK、列类型、索引及 owner。空计划先查登记与目录，不重迁。实际执行后只读计划、目录快照和阶段退出码复查。不要把历史生成 SQL 当迁移输入。 | 静态比对隔离历史 DDL，预约／历史主键 identity，两个对象 FK 和精确匹配 CHECK 存在；本轮没有迁移。 |
| 3 · 双向校验 ACL | 候选只授预约的投影 SELECT、INSERT、`UPDATE(status)`，审计实际 INSERT 列和 `SELECT(id)`（供 `RETURNING id`）。现有账号／设备 ACL 不重授。对象 owner 与 PUBLIC／角色继承一并检查。两表 19 列×4 种列权限须有 76 个比对行，目标 26 个 true，转授权及表级宽权限均为 false。已完全满足即跳过；仅完整清白状态才执行一次获批授权，部分、额外或身份异常即停。用 `ON_ERROR_STOP` 与 psql 单事务，把后置断言不通过变成事务错误，不仅返回一行 false。 | 对照生成 DDL、应用投影和三条 GRANT 文本，列与角色匹配；查询为限定别名的普通 SQL，无 PL/pgSQL 变量冲突。未执行 SQL。 |
| 4 · 监听与已加载版本 | 正式窗口内先复查 `127.0.0.1:8001` 的监听进程，核对工作目录、原 .venv、运行模式、进程父子关系、实际加载版本和启动记录，不能单凭端口、PID 或文件散列认定正确。只有确认同版本才复用；需变更时按已批准替换或空闲的 loopback 端口方案，不终止未知监听。 | 本轮 OS 只读快照看到 `127.0.0.1:8001` 已监听，PID `18648`，进程名 `python`。未确认加载 Story 2.1，不启动第二个相同端口进程。 |
| 5 · 演示数据与时间 | 另批后只选已批准的现有可用设备、不同的现有活跃学生、教师及管理员，记录脱敏标识和生产数据留存办法。先读取 DB 当前北京时间，优先取下一个北京时间自然日的两段互不相交整点时段（例如当日 10–11、14–15），再按正式半开重叠规则检查该设备的已批准及未开始待审；每个分支提交前复核开始仍严格在未来。如无合适空档、旧演示已占、设备状态改变或数据归属不确定，停止，按已批准范围重新选，不能删除原数据、清库、重放种子，也不写死验证日期。 | 无正式库数据访问，设备、账号、时段未预填为通过。正式提交本身仍受锁后规则约束。 |
| 6 · 真实 Chrome 和独立回读 | 从登录→身份→目录→详情→预约实际链接。经批准演示两角色合法提交和本人回读、一次非法非整点的 400→同页改正→201→200、同设备冲突 409、同角色异主 404、管理员直达拒绝。记录关联行和无额外写入，不记录凭据。若没有获准且自然到期的本人演示待审，只保留隔离库 FR-018 证据，不造到期正式夹具，不重等整点。 | 正式 Chrome 运行未执行。不在正式库跑 NFR 或故障注入。 |
