## 一起批准的技术取舍

### R-04 · 数据库保证单对象历史

推荐 `audit.OperationHistory` 设非空 `object_type`，和两个分别指向 `Reservation`、`Equipment` 的可空真实外键（ORM `PROTECT`、无级联删除）。数据库表规则为

```text
(object_type='reservation' AND reservation_id IS NOT NULL AND equipment_id IS NULL)
OR (object_type='equipment' AND equipment_id IS NOT NULL AND reservation_id IS NULL)
```

CHECK 禁止空、双对象及类型错配，两个 PostgreSQL 外键禁止悬空，禁止删除被引用对象后仍提交。数据库检查 NULL、双设、错配、未知类型、两类悬空外键、有效两型关联（只在隔离夹具中插入设备历史）及引用对象删除约束。非空 FK 测试在真实提交或明确约束检查时断言，不能只以 ORM 验证充数。仅实现预约系统失效追加入口，记录对象、动作、前后状态、`system` 执行者（账号空）、固定原因「开始时间已到仍待审核」、唯一 `t_decision` 及实际写历史记录时间。记录时间单独取 INSERT 语句时间或等效实际采样，不用它做业务决策，不写成提交时间。创建预约保留申请人与申请时间，不伪造审批/设备历史。拒绝泛型对象 ID（无跨表 FK），本轮不引入对象注册表、触发器或两套历史服务（没有必要，增加写入协调），也不增加占用表或 PostgreSQL 排斥约束来替代现有设备锁协议。 [D-012 / ADR-006](../../decision-log.md#d-012-2026-11-10-人工接受adr-006历史对象关联完整性约束) · [PostgreSQL 约束](https://www.postgresql.org/docs/17/ddl-constraints.html)

### 服务、授权与界面

1. 师生从设备详情点击「申请预约」，进入 `/equipment/<pk>/reserve/`；管理员无入口，直达也拒绝。以两个有标签的北京时间日期时间输入说明整点、同日、严格未来及 23:00 结束边界。HTML 步长仅提示，服务端独立校验，不能靠浏览器防绕过。申请人取服务端账号，设备取路由，额外申请人、设备或客户端时区字段不改变归属或时间解释。用现有 Django 模板、转义、会话和 CSRF。
2. POST 先授权，再进入最外层短事务。按设备主键 `FOR UPDATE`，独立重读设备当前记录和账号角色／启用状态。复核后独立执行一次 `SELECT clock_timestamp() AS decision_at`。在这个目标设备内收尾已到开始的待审，不把无关设备纳入、不向提交人返回他人的记录。语法错误可以先解析但不得让已授权、设备存在的业务无效请求在合法收尾前返回。其后判定不可用、时间无效、冲突；业务拒绝以值退出并提交合法收尾。符合条件的只创建一条待审，按同设备 `old.start < new.end AND new.start < old.end` 查冲突，已批准及未开始的待审有效。锁一直持有到 COMMIT；不使用旧状态、事务起始时钟、`skip_locked` 或事务内渲染。 [Read Committed](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-READ-COMMITTED) · [Django 事务](https://docs.djangoproject.com/en/5.2/topics/db/transactions/)
3. 事务提交后 201 明示成功并返回编号、设备、时段、提交所确认的状态和链接 `/reservations/<pk>/result/`。合法 GET 先按当前主体与编号固定一条候选；有待审才锁该设备，重读候选与权限后才采样，超过预约结束也要按需失效。无待审不加设备写锁，重复读取不追加历史。不跳到列表。非本人和不存在采用相同 404，管理员不进本人入口，匿名登录跳转。未授权不触发 FR-018 或取业务锁并且不渲染受限字段。
4. 400 时间无效。409 设备不可用或占用冲突，分别清晰提示，不展示冲突记录所有者/区间。503 确认事务失败明确说本次未成功及回滚，提交未知提示「结果待核查，请勿重复提交」，无虚构记录号，不补查或自动重试。对已送达 PostgreSQL、却没收到可靠确认的可能结果不预言。客户端断网本身不是数据库提交未知。复用 Story 1.2／1.4 现有事务边界和错误诊断，仅提取共用分类函数；数据库/锁错误不伪装成业务冲突。
