## 3. 团队实际操作及回执

- **学生、教师各一次**，分别在身份页点击「我的预约」，查看本人列表及一个本人详情，再返回列表。记录所见预约/设备状态、北京日期及起止、授权原因（如有）、详情 ID 与链接。批准测试账号在进入列表的整个窗口都无会到期的待审记录时，才把它安排为预约业务只读烟测。列表不限单设备或指定日期，必须核对账号的**完整**待审范围。空列表、无历史原因或无安全数据按实记录，不造正式夹具。
- **已预约成功页**必须用实际获批的创建操作才能取得 201。先选可用的专用演示设备和合法未来北京整点区间，核对账号权限、两条不冲突的演示时段/设备、旧服务及业务并发，写明允许的唯一增量。每个师生用新取的 CSRF 正常提交一次，记录 201、原详情链接和「我的预约」链接，点击对应入口并核对记录。**如仅获批只读，不发 POST**，该路径暂沿用隔离证据。如果结果未知先对照现有记录，不重复提交。不要用后续取消功能或 SQL 清除正式演示记录。
- **管理员及越权对照**，管理员身份页无「我的预约」，直接列表／详情应为 403。另用获批的同角色不同测试账号及无记录对照，验证两个同形 404、无预约细节。没有可用的同角色正式演示账号则标明未实做，沿用隔离同角色证据，不借真实用户登录。匿名会话 302 到登录页可单列。
- 每次当场保留下列字段，不事后推断。使用脱敏截图或 Network 记录，只保留必要可见字段，检查不包含 Cookie、密码和敏感资料。
