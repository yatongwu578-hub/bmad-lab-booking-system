- 新开 2.8 的独立 Build 会话，先读取 [课程约束](../../docs/course-requirements.md)、[已批准 AC-1～8](../planning-artifacts/epics.md#story-28-管理员取消预约并记录原因)、规划架构及 project-context，再确认 Git 起点、隔离数据库和正式独立 code-review 入口。不传入实验 A 对照组进程或历史。
- 复用现有 2.4 的本人取消事务基础、2.5 的管理员查询／详情授权、2.6/2.7 的统一设备锁和锁后判时机制，不把本人取消或拒绝的边界照搬为管理员取消。待审核在开始前可取消，到开始时保留合法 FR-018 失效；已批准在结束前可取消，包括已开始未结束，已到结束不取消，也不误失效。维修或停用不改变 2.8 时间规则。非空原因仅向有权用户展示，状态及对应历史原子提交。
- 计划用隔离 PostgreSQL 覆盖待审核开始和已批准结束的前/等/后、已开始未结束、未授权、错误 CSRF、原因、重复与失败；按正式 AC-8 复用已验证的双连接取证验证与申请、批准及失效交错。结果未知不盲判或重试。不得在正式库造样，不开发 3.1。
