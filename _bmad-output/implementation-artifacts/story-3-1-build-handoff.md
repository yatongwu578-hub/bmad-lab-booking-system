Story 2.8 已按 D-064 最终验收。3.1 仍为 `backlog`，本交接不创建实施规格、不开始开发、不运行测试或操作数据库。下一工作流用独立会话，从包含本交接的 2.8 最终交付提交核对基线，先读课程基线、正式 PRD、Architecture/ADR、Project Context、故事、Sprint 计划与状态和决策/延期台账。 [2.8 最终验收](story-2-8-final-acceptance.md) · [3.1 正式 AC-1～AC-8](../planning-artifacts/epics.md#story-31-安全变更设备状态并保留预约) · [课程基线](../../docs/course-requirements.md) · [Sprint 状态](sprint-status.yaml)

- **范围。** 仅增加可用／维修／停用状态转换及授权读取目标设备的既有变更历史。保持编号和描述等基础信息及预约关联不变，非法枚举拒绝，同状态不写历史。历史读取只读，不加无必要的写锁、不触发 FR-018。不要重建设备编辑、预约查询、取消或日志管理。
- **一致性。** 复用同一设备行锁、锁后权限复核和重读、唯一判时、状态与历史同事务及提交未知不重试。维修停用不自动动预约，恢复不复活终态；申请和批准继续按各自锁后设备状态决定，预约和设备状态分别展示。
- **验收重点。** 在隔离 PostgreSQL 逐项覆盖 AC、T-01～T-04 及 NFR-002。用独立连接证明状态转换与申请、批准、两类取消的双序以及预约查询固定候选交错；验证设备历史授权、目标范围、真实记录及空结果，区分确认回滚和提交未知。2.8 的 159 项 Django、36 组探针及 2.1 的 NFR-001 历史标准组是前置证据，不是 3.1 实测。
- **待核对。** 在新 Build 的 Checkpoint 1 核查设备状态列与历史关联的既有迁移及实际列权限；如果 3.1 确实需要增量，列出精确差异和影响，未授权不迁移、不 GRANT。只用 `127.0.0.1:5433/test_lab_booking` 测试，不将 2.8 的正式授权延伸到 3.1。Sprint 8/5 和实验 A 保持原口径。
