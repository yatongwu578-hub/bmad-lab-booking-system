## 先只读验证，再启动独立端口

在仓库根目录的普通 Windows PowerShell 执行。使用项目原 `.venv` 的 Python 3.13.17 和现存受保护密码文件。只在默认路径不同且当前终端未设好 `PGPASSFILE` 时传 `-Passfile '<现存受保护的绝对路径>'`，不要打印文件内容。与三位组员共同确认选定设备在烟测窗口内无其他业务操作。

```powershell
& '.\_bmad-output\implementation-artifacts\verify-story-2-2-runtime.ps1'
```

它先校验新独立批次所认证的运行源码和文件集。以 `lab_booking_app@127.0.0.1:5433/lab_booking` 的 **READ ONLY** 事务核对 PostgreSQL 17.12、Read Committed、现有两项预约／审计迁移、R-04 对象及 D-042 精确有效与显式 ACL。复用已审核查询，包括字段限定、权限矩阵、表级／转授／序列负对照及空 ACL 保护。不会运行旧部署代码。已有权限足够，漂移即停，不尝试补迁移或重授。

只有原生进程退出 0 且出现唯一 `STORY22_RUNTIME_READONLY_BEFORE_OK` 时才继续。保留打印的新回执目录。默认启动独立的 `127.0.0.1:8002`，使用自己的前台进程和 `--noreload`。端口占用则停止，不连接、接管或结束 8001 的旧服务。需要时在命令增加 `-Port <另一个空闲端口>`，不得使用 8001。看见本次前台实际启动监听后再访问，不因浏览器存在旧页面而认定启动成功。

## 三个角色实际操作

1. 使用新的 Chrome 浏览器配置文件，不复用 8001 的 Cookie。逐个使用现有学生、教师和管理员账号。不要把账号密码、会话令牌或其他受限信息写进回执。登录可能按既有权限更新会话和最后登录时间，不属于预约业务写入。
2. 从打印的新端口进入 `/login/` → 设备目录 → 指定演示设备详情 → 实际在日期控件选日提交。只用只读前置报告列出的**无待审**日期。核对 URL 中的目标设备、日历日期、实际状态码、设备状态、区间和说明、返回详情及目录。不操作预约创建、管理或取消入口。
3. 优先核对已识别的空日。如有无待审的现存批准或历史日期，额外核对该分组及隐私。无合适数据时如实写明分支未作正式烟测，沿用隔离实证，不为凑证据造数据。可用无登录的新会话核对单独的占用入口拒绝。分别记录角色、设备、日期、URL、实际响应及人工结论，不记为自动脚本验证。
