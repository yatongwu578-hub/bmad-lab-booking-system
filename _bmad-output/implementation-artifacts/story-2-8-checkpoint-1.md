### T-01 和 T-02 · PostgreSQL 交错与时钟

| 交错 | 按先后分别断言 |
| --- | --- |
| 取消／取消 | 首次成功、后手重读终态后拒绝，仅一条取消历史。 |
| 批准／取消 | 取消先则批准拒绝；批准先且取消判时未到结束，后手从已批准合法取消，依序两条历史，且取消前状态为已批准。批准先、后手等锁越过结束则仍已批准，不误失效。 |
| 拒绝／取消 | 拒绝先则取消拒绝；取消先则拒绝失败。仅先手的一次有效转换和相应历史。 |
| 申请／取消 | 对未来重叠时段，申请先应明确冲突，取消随后释放；取消先则合法申请成功，最多一条有效占用。 |
| 取消／查询及按需失效 | 开始前取消先提交时，查询重读取消且不误失效；查询先观察合法待审核时不得提前改状态。到期的两种先后只形成一条系统失效，不能再取消或复活。分别覆盖管理员及本人或占用授权查询路径。 |
| 等锁跨边界／判定后提交跨边界 | 分别证明开始、结束的真实等锁越界判定；另证明锁后判时仍合法，仅提交跨界仍按该唯一判时处理。不得把可控时钟的精确相等断言冒充真实时钟实测。 |

用短唯一设备编号（模型上限 32）、受控未来时段和专属夹具；记录连接 PID、等锁关系、判定时间及状态/占用/历史前后数据。用既有探针的同步点和独立提交回读，不用随机抢占替代顺序实证。
