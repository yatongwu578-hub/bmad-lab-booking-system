## 第2轮：PRD需求检查

- **检查人：** 罗思婕
- **检查日期：** 2026-10-31

- **我认为合理的功能：**

  1. **查看设备（FR-003）：** 学生可以查看设备列表、编号、位置和状态。
  2. **查看空闲时间（FR-004）：** 可以按设备和日期查看占用时段，区分被占用与可申请时间。
  3. **提交预约（FR-005～FR-008）：** 可以选择具体设备和时间提交申请；系统检查时间、设备状态和预约冲突，成功后显示待审核。
  4. **查看申请结果（FR-009）：** 可以查看自己的待审核、已批准、已拒绝、已取消预约，并查看拒绝或管理员取消的原因。
  5. **取消本人预约（FR-010）：** 学生可以取消自己尚未开始的待审核或已批准预约，取消后释放时段并保留记录。
  6. **管理员审核（FR-011～FR-014）：** 管理员可以查看申请、批准或拒绝申请，拒绝和取消时必须填写原因。
  7. **故障和停用管理（FR-016、FR-017）：** 管理员可以维护设备，将设备设为维修、停用或恢复可用；维修和停用后禁止新申请。

  角色划分也比较清楚：学生和教师权限相同，只管理自己的预约；管理员负责审核和设备维护。普通用户不能查看他人的申请详情，符合基本隐私要求。正常的“查询—申请—审核—查看结果—必要时取消”流程完整。

- **我发现遗漏的功能：**

  1. **超时未审核申请的收尾处理（FR-013、FR-014）：** 开始后不能批准或拒绝，结束后也不能取消，可能永久保留“待审核”。缺少明确的处理办法。
  2. **受故障影响预约的查找入口（FR-011、FR-017）：** 已要求管理员人工处理，但没有明确能否按设备筛选尚未结束的预约。建议补充，避免逐条查找造成遗漏。

- **我认为多余的功能：**

  检查后认为合理，暂未发现明显多余的业务功能

- **我看不懂或不明确的要求：**

  1. **FR-006：** 只允许整点、至少1小时、最晚23:00结束，但没有开放时段限制。是否意味着凌晨也能预约？需要确认是否符合实验室实际管理规定。
  2. **FR-005、FR-007、FR-013：** 待审核申请立即占用时段，且没有自动过期释放。如果管理员迟迟不审核，其他人就无法申请该时段，处理规则需要确认。
  3. **FR-017：** 设备停用后，原预约仍可能显示“已批准”。不明确学生查看预约时，是否能同时看到设备已维修或停用的提示。
  4. **A-001：** 时间口径仍是待确认假设，建议明确统一使用北京时间。
  5. **A-002、FR-007：** 同一人可以同时预约不同设备，是否符合实际需要。

- **我建议修改的内容及原因：**

  1. **完善FR-013、FR-014的超时处理规则。** 明确到开始时间仍未审核的申请如何结束处理，避免过往申请一直显示待审核。具体采用自动过期还是人工处理，由小组讨论决定。
  2. **补充FR-011、FR-017的设备筛选要求。** 管理员应能按设备查看受维修、停用影响且尚未结束的预约，方便及时处理。
  3. **补充FR-009的设备异常提示。** 学生查看本人预约时，应能看到设备当前维修或停用状态，减少把“已批准”误认为仍可正常使用的情况。
  4. **确认FR-006的可预约时段。** 根据实验室实际开放时间决定是否限制凌晨预约，并确认整点和最少1小时是否合适。
  5. **确认A-001、A-002后再定稿。** 明确统一时间口径和同一人同时预约多台设备的规则，避免开发和测试时理解不一致。
